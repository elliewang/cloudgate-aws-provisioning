# Host CloudGate as a team-accessible website (Render)

## 1. Publish the source
1. Create a new GitHub repo (prefer **private** for a team demo).
2. Upload the **contents of this folder** to repository root; `render.yaml`, `Dockerfile`, `pom.xml`, and `src/` must be at top level.
3. Commit to `main`. Go to **Actions** and inspect the CI runs (some security scans can fail on newly published vulnerabilities; resolve findings rather than disabling checks).

## 2. Deploy using Render Blueprint
1. Open https://dashboard.render.com/ and sign in.
2. Choose **New > Blueprint** and connect your GitHub repository.
3. Confirm the `render.yaml` configuration. Select the free service and free database for a short demo. Review the planned resources **before** approving creation.
4. For `DEMO_LOGIN_PASSWORD`, enter a strong, unique demo password. **Do not put this password in GitHub**. `DEMO_LOGIN_USER` is `teamdemo` unless changed in Render.
5. Apply the Blueprint, wait for the Docker build and database to be deployed, and check Render service logs for successful startup.
6. Open the HTTPS `https://<your-service>.onrender.com` URL generated by Render (the exact hostname comes from your service settings). The browser requests HTTP Basic credentials. Share the URL and demo credentials separately with authorized colleagues.
7. Verify `/healthz` returns status `UP` (no login). At `/` sign in and create a sample intake; switch the demonstration roles to show approval steps. Review Audit Trail.

## 3. How the demo works
- **Real**: Java 21 Spring Boot, JPA, Render PostgreSQL, forms, CRUD, demo role transitions, audit records, GitHub Actions Maven tests, Terraform plan + OPA policy checks, ephemeral Docker test deployment.
- **Simulated**: AWS provisioning. The web portal's state transitions are **not** connected to GitHub Actions runs, approvals, GitHub identities, or actual deployed AWS resources.
- **Login**: A single shared HTTP Basic login protects the hosted portal, but it is **not individual authentication or reliable role-based authorization**. The in-page role selector simply sends a client-controlled header. Don't enter secrets or actual company information, and do not claim it enforces enterprise RBAC.
- **CI vs hosted deployment**: GitHub Actions runs validation and a separate ephemeral Docker demo. Render builds its own container when the linked main branch has passing checks; it is not deployed by the GitHub Actions demo-deploy job.

## 4. Limitations, pricing, and operations
- Per Render documentation checked November 2026, Free PostgreSQL expires after **30 days**, with **no backups**. It has a 1 GB storage cap. Free web services can spin down on inactivity and have CPU/memory and usage limits. See https://render.com/docs/free.
- Free hosting is for demonstration only, not production, regulated, or sensitive data.
- Database schema uses `ddl-auto: update`, and audit rows are ordinary mutable DB records. Use Flyway, append-only verified logs, SSO/OIDC, server-enforced RBAC, HTTPS session/cookie protections, rate limiting and least-privilege before any real internal/production use.
- To retain team demo data beyond 30 days, select a paid persistent PostgreSQL plan and configure backups. Confirm current prices before upgrading.
- To restrict access, share credentials only with intended colleagues and rotate in Render Dashboard after demonstration. HTTP Basic credentials may remain cached by browser; use an incognito/private session for demos.

## 5. Local mode
`docker compose up --build -d` then http://localhost:8080. Local mode preserves the original unauthenticated role-selector behavior. Do not expose this local port to the public internet.

## 6. Troubleshooting
- `401` at `/`: browser needs `teamdemo` + `DEMO_LOGIN_PASSWORD`.
- `500`/database connection failure: check PostgreSQL has provisioned, `DATABASE_URL` is injected, and both services are in the same Render region.
- Render deploy pending: inspect GitHub CI check states; `autoDeployTrigger: checksPass` waits for successful checks, and GitHub protected environments can require approval.
- Web app goes to sleep: Free web service spins down on inactivity; retry after it wakes.
- Always inspect the actual generated Render URL; do not assume a specific hostname is available.
